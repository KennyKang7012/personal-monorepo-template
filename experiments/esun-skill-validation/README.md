4. 確認本機電腦開機、App 執行、專案可存取，以及瀏覽器與檔案操作的既有權限可用；不藉測試擴大權限。

## 執行前檢查與停止條件

- 測試啟動前確認原 Project 沒有 active、待人工處理或尚未完成的作業；若仍有活動或狀態不明，停止當次測試，不操作瀏覽器，也不干預原任務。
- 獨立目錄與聊天不等於完全隔離，電腦、瀏覽器與登入狀態仍可能共用。唯讀狀態快照只能降低重疊風險，不能宣稱提供原任務與測試共用的互斥鎖。
- 對應交易日不明、下載窗口未開放、登入過期、驗證碼、權限不足、工具或網站失敗時，依 skill 停止並保存原因；不繞過驗證、不無限重試。
- 保留所有既有檔案；測試不操作上傳、送出繳交、策略參數、開發引擎、部署、Push 或 Merge。
- 不在測試紀錄保存密碼、Token、Webhook 或其他憑證。

## Decision Criteria

| 驗收項目 | 通過條件 |
| --- | --- |
| 自動啟動 | 有排程實際啟動與結束證據，不以建立成功或 Session ID 當作完成 |
| 載入 skills | 有讀取正式文件的執行紀錄及版本雜湊 |
| 成功下載 | 官方日期明確、下載事件完成、JSON 非空且可解析、來源與測試目的檔位元組一致、記錄 SHA-256 |
| 完整截圖 | 當時所有可見頁面、日期、組別、分頁與溢位內容有對照；圖片完整解碼，回看長圖零未覆蓋像素 |
| 無人介入 | 執行期間沒有人工操作或要求續跑；否則標示人工協助，不算完整無人看守通過 |
| 產物隔離 | 最終產物均在本次 run-id 內，正式資料區與既有備存未被寫入或覆蓋 |
| 原排程保護 | 原 ai、ai-2 設定未變，未被測試觸發、暫停或修改；沒有觀察到執行重疊，並保留狀態快照的限制 |
| 如實回報 | 分別記錄成功、正常跳過、安全停止、未驗證或失敗；一個子項通過不代表整體通過 |

下載與截圖均完成相應驗證，且無人工介入，才能標示本次完整通過。安全停止是必要行為，但不等於成功下載分支已通過；模擬測試也不能代替實站驗收。
